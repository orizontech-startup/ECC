# Documentation and Handoff Standard

- Preserve a frozen scope/roadmap when the project has one; changes require explicit decision, not drift.
- Track the current phase, completed work, blockers and exact next executable step.
- Use the project's canonical documentation structure; avoid duplicate top-level files.
- Record material architecture decisions with rationale and consequences.
- Document production URLs, repositories, environments and deployment paths without embedding secrets.
- Handoffs must state what was actually tested and what remains unverified.
- Include relevant commit/PR/deployment identifiers so another session can resume without guesswork.
- Separate facts from assumptions and planned work.
- Keep operational runbooks for recurring production tasks that cannot safely depend on memory.
- End substantial work with go-live status and a concise remaining-blockers list.
