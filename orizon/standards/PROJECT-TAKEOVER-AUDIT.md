# Project Takeover Audit

Use this standard whenever Orizon Tech assumes responsibility for an existing software project.

- Inventory repositories, branches, deployment targets, domains, databases, cloud accounts and third-party services.
- Confirm what is actually live before trusting documentation.
- Establish ownership of source, infrastructure, billing, secrets and external accounts.
- Map architecture and critical user journeys before refactoring.
- Run baseline build, tests, lint/typecheck and runtime smoke tests without changing behavior.
- Record current production defects separately from new regressions.
- Identify abandoned code, duplicate environments, broken CI/CD and undocumented manual deploy steps.
- Recover product scope and roadmap from code, issues, docs and stakeholder input; freeze the agreed baseline.
- Create a risk register covering security, data loss, vendor lock-in, performance and operational fragility.
- Define the next executable phase with clear acceptance criteria and go-live gates.
