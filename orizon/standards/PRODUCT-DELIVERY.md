# Product Delivery Standard

- Start from an explicit scope, roadmap or acceptance criteria and keep it frozen enough to prevent drift.
- Divide large programs into phases with clear done conditions and dependencies.
- Report phase progress from evidence, not intuition.
- A phase is complete only when its required backend, frontend, data, tests and deployment work are complete.
- Maintain a single canonical current-state/handoff source per project.
- New requests that alter scope should be identified as scope changes before implementation.
- Prioritize blockers that prevent end-to-end user value over isolated internal completion.
- When Orizon assumes an existing project, audit current reality before promising a roadmap.
- Surface technical debt separately from the committed delivery scope unless it blocks production.
- Always state the next executable step after a milestone.
