# Mobile-First UX Standard

- New user-facing interfaces are designed mobile-first unless the product explicitly requires desktop-first operation.
- Start layout validation at narrow phone widths before expanding to tablet and desktop.
- No critical action may depend only on hover, precise mouse movement or desktop-only UI.
- Touch targets must be comfortably tappable and separated from destructive neighbors.
- Respect safe areas, viewport changes, virtual keyboards and mobile browser chrome.
- Avoid fixed-width tables and dialogs that overflow the viewport; provide responsive alternatives.
- Test iOS Safari and Android Chrome for critical flows when the product targets mobile web.
- Preserve desktop productivity while making mobile a first-class experience, not a collapsed afterthought.
- Use responsive typography, spacing and media; prevent layout shifts and horizontal scrolling.
- Optimize images, bundles and initial rendering for constrained mobile networks and devices.
- Ensure forms use correct input types, autocomplete and keyboard behavior.
- Support accessible focus order, labels, contrast and reduced-motion preferences.
- Test landscape only where it matters, but never break it accidentally.
- A feature that works on desktop and is unusable on a supported phone is incomplete.
